sqlh - SQL Server query tool for agents. Read-only by default; compact typed output.

USAGE
  sqlh [connection] [options] -Q "SQL"          (or the SQL as the only argument)
  sqlh [connection] [options] -i file.sql [-i more.sql]     (or SQL on stdin: <SQL> | sqlh ...)

EXAMPLES  (same in cmd.exe, PowerShell and Git Bash)
  sqlh -S myserver -d AppDb -Q "SELECT TOP 5 * FROM dbo.Orders WHERE Status = 'Open' ORDER BY Id DESC"
  sqlh -S myserver,1433 -U reader -d AppDb -i report.sql   (password: env SQLCMDPASSWORD)
  sqlh --profile dev -Q "SELECT TOP 0 * FROM sys.dm_exec_requests"   (columns and types only)
  sqlh --profile dev -i "my queries\report.sql" -o report.txt
  SQL with " $ % ` or several lines goes in a file (-i). Quote -S "host\inst" and paths with spaces.
  Paths: C:/dir/f.sql works everywhere; C:\dir\f.sql needs quotes in Git Bash; /c/dir/f.sql is Git Bash only.
  Piped non-ASCII text becomes "?" or an error unless the shell sends UTF-8: cmd.exe needs chcp 65001
  first, Windows PowerShell 5.1 needs $OutputEncoding = [Text.Encoding]::UTF8 first. -Q and -i don't.

CONNECTION
  --profile NAME  saved connection (env SQLH_PROFILE). Without -S, the default profile is used
  -S server       host | host\instance | host,port   (env SQLCMDSERVER; default .)
  -d database     (env SQLCMDDBNAME); default: the profile's, else the login's (often master)
  -E              Windows integrated auth (the default when there is no -U)
  -C              trust the server certificate (self-signed servers); profile add NAME -C saves it
  -U login        SQL login (env SQLCMDUSER); password from the profile or SQLCMDPASSWORD; no -P
  -Ns | -Nm | -No encryption strict | mandatory (default) | optional
  -K ReadOnly     read-only application intent      -M  multi-subnet failover
  -l seconds      login timeout (default 15; 0 = none); one attempt, no retries

EXECUTION
  -i file         input file, repeatable; "-i -" reads stdin. UTF-8, or UTF-16 with a BOM
  -v n=v ...      values for $(n); environment variables also resolve. -x turns this off
  -c word         batch separator (default GO; "GO 3" runs a batch 3 times)
  -t seconds      per-batch query timeout, also for a stalled reader (default 60; 0 = none)
  --lock-timeout S      seconds a statement waits for a lock, then error 1222 (default 10; 0 = none)
  --read-uncommitted    read-only runs only: read without waiting for writers; rows may be dirty
  --allow-write   permit writes. Without it, writes other than to #temp/@table are refused
                  before anything runs, and all batches run in a transaction that is rolled back.
                  This guards against accidents; it is not security. Use a read-only login.
  --check         compile only (SET NOEXEC ON): finds syntax errors and unknown columns, not missing tables
  --continue-on-error   run later batches after one fails (default: stop)

OUTPUT
  --format F      text (default) | json (one document; exit status last) | csv (data; -- lines on stderr)
  --max-rows N    rows shown per result set (default 100; 0 = all). Read-only runs count the rest for
                  250 ms, then stop: "≥N" means the rest of that batch did not run (--exact-count counts all)
  --max-cell N    characters per value (default 500)   --max-results N  result sets (default 20)
  --max-output N  total output bytes (default 1000000; 0 = no limit); the run still finishes
  -o file         write output to a file (replaced whole when the run ends; never an input)
  --verbose       connection diagnostics on stderr

PROFILES  (passwords live in Windows Credential Manager, never in files or arguments)
  sqlh profile add NAME -S server [-d db] [-U login] [-C] [--write-policy deny|flag|allow] [--new-password]
  sqlh profile list | test NAME | rm NAME     (add asks for the password; new profiles deny writes)

FORMAT
  "-- " lines are metadata: "-- result N", a header of name:type columns, tab-separated rows,
  "-- N rows". NULL is NULL; the string 'NULL' is \NULL. Escapes \t \n \r \\ (one backslash) cover
  values and the names and paths in -- lines. A cut value ends …[+N]. Errors map to input lines.
  The last line is "-- ok: ..." or "-- failed (exit N): ...", unless exit 7 or 10 cut it off.

EXIT CODES
  0 ok  1 SQL error  2 connect/login failed  3 usage  4 timeout  5 write blocked  6 cancelled
  7 output not delivered (the reader went away or stalled, or -o failed)  10 internal error
